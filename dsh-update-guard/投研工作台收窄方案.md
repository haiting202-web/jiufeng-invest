## 二、现状：每轮固定 15,259 tokens（2026-09-18 用 API usage 实测复核）

数据源：`~/.dsh/sessions/<ws>/<session>/session.v3.jsonl.zstd`（**多帧 zstd，追加写**）。
- `request/header` 事件 → `config`（provider/model）+ `tools`（完整工具数组含 input_schema）
- `system/message` 事件 → **system prompt 全文**（不在 header 里！）
- `user/message` 事件（`source.kind === 'skill-catalog'`）→ **skill catalog 全文**（也不在 header 里！）
- `assistant/message` 事件 → **`usage.inputTokens` = API 返回的真实输入 token 数（权威）**

复核工具：`量化每轮token.mjs`（`node 量化每轮token.mjs [会话目录]` / `--json`）。
它按内容类型分别折算（中文密集 ÷1.5、英文 ÷3.96、JSON ÷4.7，系数由本机 usage 反推），
在 ai-finance 实测会话上 **估算 15,205 vs 真实 15,259，偏差 −0.4%**。

| # | 来源 | 字符 | 实测 tok | 可省 | 说明 |
|---|---|---|---|---|---|
| ① | system prompt | 7,244 | **1,829** | ~340 | 只占 12%，可动的不多 |
| ② | skill catalog | 9,894 | **6,596** | **~6,020** | 89 个 skill —— 最大且最干净的一块 |
| ③ | 工具数组 | 31,853 | **6,780** | ~2,710 | **46 个工具**（25 preset/host + 21 个 dsh-finance-tools） |
| | **合计** | **48,991** | **15,205** | **≈ 9,100（60%）** | 真实首轮 usage = 15,259 |

> **修正上一版方案的偏差**（原稿写"工具 catalog 6,734（25 个工具）+ 可省 3,973"）：
> 6,734 实际是**全部 46 个工具**的合计（21 个金融工具当时没算进去），单个工具的真实成本比原表低约 12%；
> 因此 A 类实际可省 ≈2,710（不是 3,973）。总账从"省 75%"修正为 **省约 60%（15,259 → ≈6,100）**。
> 结论方向不变：**skill catalog 仍是最值钱的一块**，A 类仍是值得做的第二块。

### B 类 · skill catalog（省 ≈ 6,300）—— **本轮重大发现**

**88/89 是侧边栏的同名孪生**，且 DSH 正文只是「侧边栏 prompt + 模板壳」。
既然用户的实际入口是侧边栏（自带完整 prompt、还有表单卡），那 DSH 侧**只为"模型自主想起来"而存在**，而这件事 88 个重复项几乎用不到。

| 处置 | 数量 | tok |
|---|---|---|
| **常驻**（建议 3 个） | `bull-bear-debate`（唯一独有）· `technical-analysis` · `stock-comparison`（最可能被其他分析中途引用） | ≈ 250 |
| **转按需** | 其余 86 个 | 省 ≈ 6,300 |

**机制**（四条源码证据，非 hack）：

```yaml
# SKILL.md frontmatter 加一行
disable-model-invocation: true
```

- `dsh-tool-skill:217` `snapshot.skills.filter(isModelInvocable)` → **不进 catalog，省 token**
- `dsh-tool-skill:181-183` 用户调用路径**只校验 `userInvocable`，完全不看 `modelInvocable`** → **打 `/名字` 仍加载完整正文**
- `dsh-client-ui-skill/client.js:281-291` `/` 补全菜单**仍包含它**，标注「仅用户」（`menu.userOnly`）
- ⚠️ **必须用连字符形式**。旧写法 `modelInvocable` / `disableModelInvocation` 会被 `rejectLegacyInvocationKey` **直接抛错**

**代价**：摘出的 skill 模型不会自主使用，必须显式 `/`。

**工具已就绪**（`dsh-update-guard/`，已通过 89/89 端到端验证，**当前磁盘 0 改动**）：
```bash
node 管理skill分级.mjs --status                     # 只读看账
node 管理skill分级.mjs --selftest                   # 证明改写安全（89/89，178 次内存往返）
node 管理skill分级.mjs --apply "skill-分级清单.json"           # 预演
node 管理skill分级.mjs --apply "skill-分级清单.json" --write   # 落盘（自动备份）
node 管理skill分级.mjs --rollback                   # 回滚
```
> 需把 `skill-分级清单.json` 的 `keep` 数组从「常驻 28」改为「常驻 3」。
> 验证方式：用 DSH 自带 `yaml` v2.9.0 + 复刻其 `parseFrontmatter` 步骤解析 89/89 通过。

## 六、两句必要的实话

**一、这次精简不会让冷启动明显变快。** 它解决的是"**每轮更省、模型更专注**"——
每轮固定前缀从 15,128 降到 ≈ 3,800，百炼免费额度（每模型 100 万 tokens）从"三天见底"变成"十天以上"。
启动慢的大头大概率仍是 **Windows Defender 实时扫描**（给 `D:\Program Files\DSH Desktop` 与 `~/.dsh` 加排除项），那是另一个动作。

**二、侧边栏有一处可优化（但属冻结范围，仅记录不执行）**：
101 条 prompt 中 **26 条短于 200 字**（如 `short-interest` 仅 164 字），而 DSH 侧的 `数据获取规范` 段（Agent 应优先调用的 21 个金融工具清单）**侧边栏 prompt 里没有**。
→ 未来若解冻，值得把这 1,100 字符的工具清单提到侧边栏注入模板里，一次性惠及全部 101 个技能。
