# 多空辩论引擎 — 技术参考

> 面向开发者：辩论引擎的核心设计原理和评分算法

## 1. 辩论流程

```
用户输入股票
    │
    ▼
┌─────────────────┐
│  数据采集层      │ ← 联网搜索 / 用户输入
│  (PE/ROE/营收等)  │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  模式判定        │
│  有数据 → 客观模式 │
│  无数据 → 主观模式 │
└────────┬────────┘
         │
    ┌────┴────┐
    ▼         ▼
┌──────┐  ┌──────┐
│看多生成│  │看空生成│  ← 并行调用两台 LLM
│🐂     │  │🐻     │
└──┬───┘  └──┬───┘
   │         │
   └────┬────┘
        ▼
┌─────────────────┐
│  裁判评分        │  ← 第三台 LLM 独立裁决
│  四维加权        │
└────────┬────────┘
         ▼
┌─────────────────┐
│  格式化输出      │
│  完整/精简双版   │
└─────────────────┘
```

## 2. 评分算法

### 2.1 四维加权矩阵

| 维度 | 权重 | 评分标准 |
|------|------|---------|
| 论据质量 | 30% | 论点是否有具体支撑、是否针对标的而非泛泛而谈 |
| 逻辑严密 | 25% | 论证链条是否完整、是否存在跳跃或偷换概念 |
| 数据支撑 | 25% | 引用的数据是否可验证、是否来源可靠 |
| 风险评估 | 20% | 是否识别到关键风险/机会、是否有尾部风险意识 |

### 2.2 裁决逻辑

```
if |bull_score - bear_score| <= 1.5:
    verdict = NEUTRAL
elif bull_score > bear_score:
    verdict = BULL
else:
    verdict = BEAR

risk_level:
    总分差 > 3 且一方置信度 > 80 → low
    总分差 = 0 且双方置信度均 > 70 → high (高度不确定)
    其他 → medium
```

## 3. 质量约束机制

### 3.1 禁止稻草人论证

要求每条反方观点都必须构建**最强版本**的对手方论证。
裁判需要检查：如果我是对手方，我会认同这个总结吗？

### 3.2 置信度差距上限

`|bull_confidence - bear_confidence| <= 40`

防止一方盲目乐观、一方过度悲观，确保辩论有实质意义。

### 3.3 数据追溯性

- 客观模式：每条数据引用必须标注来源（"据2025Q3财报"）
- 主观模式：必须标注"主观判断"或"行业惯例"

## 4. 输出策略：小红书 vs 专业版

| 维度 | 小红书版 | 专业版 |
|------|---------|--------|
| 字数 | ≤500字 | 不限 |
| 论点 | 每个角色2-3条核心论点 | 每个角色3-5条完整论点 |
| 表格 | 仅裁决表 | 全部表格 |
| 估值 | 定性判断（合理/偏高/偏低） | 定量区间 + 敏感性 |
| 互动 | 必有投票引导 | 可选 |
| Emoji | 精简 | 丰富 |
